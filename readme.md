# 项目背景

日常工作场景中需要处理的电子文档大致可以分成两类：

1. **人工编写的文档** — 最常见的是人工撰写的邮件，格式自由、风格各异
2. **模板生成的文档** — 基于程序或模板（以下统称模板）再填充动态数据所生成的具有特定格式的文档，例如大部分银行的信用卡账单、由程序发出的固定格式邮件、预定义的表单等

这些文档中包含的信息通常需要人工阅读理解，然后收集到下游程序或数据集里，很消耗人力并且可能出错，因此存在对文档进行自动化信息提取的需求。

**本项目只针对模板生成的文档**，对于人工编写文档的信息提取则不在考虑范围。

# 解决思路

对于任何待处理文档，先判断是否属于模板生成；如果是，则用预定义的信息提取规则进行提取和校验，最后输出结构化的信息。
整个过程必须尽量少依赖人工干预或者标注数据的输入，完全自动化的程度，以及对模板未知的文档处理能力将是衡量该方案有效性的重要指标。

```
输入文档 → [模板检测] → 是模板? → [规则提取 + 校验] → 结构化输出
                      ↓  否
                    忽略/标记人工处理
```

# 模块划分

本项目分为两个核心模块，各自独立实现：

| 模块 | 说明 | 文档 |
|------|------|------|
| **模板文档检测** | 判断文档是否由模板生成，并进行模板分类 | [docs/template_detection.md](docs/template_detection.md) |
| **预定义规则的信息提取** | 对已识别模板的文档，按规则提取结构化信息 | [docs/information_extraction.md](docs/information_extraction.md) |

# 技术栈建议

| 模块 | 候选技术 |
|------|----------|
| 模板检测 | TF-IDF + 余弦相似度 / doc2vec / 规则引擎 / 聚类 |
| 规则引擎 | 自定义 DSL / JSON Logic / 嵌入脚本 |
| 文档解析 | Apache Tika / PyMuPDF / pdfplumber / python-docx |
| 输出存储 | JSON / SQLite / PostgreSQL |
| 运行时 | Python 3.11+ / Node.js |

# 开发路线

1. **Phase 1 — 模板检测**：实现模板文档检测与分类器（当前阶段）
2. **Phase 2 — 核心框架**：实现规则引擎与提取管线
3. **Phase 3 — 文档解析适配**：支持 PDF、DOCX、HTML、邮件 .eml 等格式
4. **Phase 4 — 管理与运维**：可视化规则编辑器、模板库管理、提取结果审计
